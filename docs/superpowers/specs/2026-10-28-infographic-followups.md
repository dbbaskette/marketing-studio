## Document capture (#173)

Keep schema-1 project compatibility while extending allowed source kinds and bounded metadata. A single checked capture function persists immutable original bytes and normalized text independently, hashes, location spans, extractor identity, warnings and acknowledgment, origin revision and replacement lineage. Derive IDs from content plus capture metadata so account revision changes do not silently alias old provenance. Revalidate stored raw/normalized/coverage identities before proposing, checking or sharing. Source dependency changes clear approval through current Store transitions.

DOCX: stdlib zip/XML only, bounded archive inventory/expansion, no symlinks/encrypted paths/entities/external relationship fetch, paragraph/table spans and explicit warnings for unsupported drawings/headers/footnotes. PDF: explicit installed pdftotext; no runtime provisioning/OCR/provider upload. Disposable owned input/output, bounded execution/output, page formfeeds retained as locations; scanned/empty pages are named gaps. Unsupported .doc is actionable. HTML: stdlib parser strips scripts/styles, never follows links. UI file picker/body bounds and CLI source command agree. Tests synthetic ZIP/XML/PDF fixtures; actual extraction acceptance only with explicitly available reader.

## Permissioned remote intake (#174)

Native account preference is email only; gcloud lookup occurs solely on explicit Google action, token in memory and fixed Google API request headers, never in settings/worker environment/errors. No automatic account switch or login. Reuse existing gcloud account convention and safe bounded API design through independent shared core transport, not importing another studio pipeline. Read Drive metadata before/after Docs structured JSON (includeTabsContent=true); require stable version/modified time, account permission/canDownload. Retain revision/hash even when opaque Docs revisionId is not available to a reader. Parse all selected tabs, paragraphs and tables; images/unknown structures become coverage warnings. No source-content publication or permission mutation.

Public URL action is separate from pasted text. Shared research_sites URL validation, HTTPS/443 only, no embedded credentials/private/loopback/link-local IPs. Resolve every redirect hop and reject any non-global answer, connect to validated IP while preserving TLS host validation, no proxy escape or automatic credential forwarding. Bound hops/time/bytes/content type. Unknown/network failures preserve existing content. Automated tests inject DNS/HTTP/account transports; no real account or fetch.

## Google Docs delivery (new issue)

Publish only an exact currently approved delivery and latest checked visual review. Build a bounded DOCX containing the approved PNG with meaningful alt text, editable text/source notes and page dimensions, then convert via fixed Drive multipart upload to application/vnd.google-apps.document. This avoids exposing a private PNG through a public image URL. New document only; no original overwrite and no sharing/permission change. Optional destination folder must be explicit and checked. Google account/destination choice is shown before publishing.

Durable delivery intent before the only write; bind request ID, revision, approval/checks/scene identities, chosen account/destination and payload hash. Use private appProperties request identity and read-only reconciliation after uncertain responses. Reopening/repeated ID never blindly republishes. Remote result stale after local edit stays historical and cannot claim current approval. Cancellation does not promise remote cancellation. PDF and the other local formats remain available if Google is unavailable. No auth tokens in persisted payloads, errors or logs. Test DOCX package structure/image/text/size, fixed destinations, scope failures, uncertain outcomes, duplicate IDs, races and recovery with fake transports.

Official references checked: https://developers.google.com/workspace/drive/api/guides/manage-uploads ; https://developers.google.com/workspace/drive/api/reference/rest/v3/files ; https://developers.google.com/workspace/docs/api/how-tos/tabs ; https://developers.google.com/workspace/docs/api/reference/rest/v1/documents/get . Workspace create does not support pre-generated IDs, so application request metadata/reconciliation is required.

## Reviewed research (#175)

Use core research_contract schema-2 read_bundle/Workflow verification, selected installed helper revision and exact dossier/artifact/capture digests. Explicit optional import of complete independently reviewed output; no image-provider grounding or public fetch in supplied-only mode. Capture the manifest, report, brief, evidence, facts, source snapshots and allowed originals into an owned immutable private research folder. Retain purpose/audience/scope/source mode/helper revision/review/counterfacts/gaps. Verify owned copies on use; stale/missing captures block claims/approval. Feed reviewed brief first and qualified facts as located supplied evidence, never promote unsupported claims automatically. CLI/UI expose preparing the infographic-purpose research brief and importing verified research. Do not promise in-app public research beyond implemented capability; external Harness Research can produce the bundle for explicit import. Tests use real pinned helper synthetic bundles and injected status/transport, never providers.

## Handoffs/team (#176)

Import only explicitly selected supported material from a validated Blog Studio/Presentation Studio/Training Studio workspace inventory, with no symlinks/hidden credential paths; snapshot selected bytes/hash/studio/item/relative path. Original change requires explicit refresh/replacement, never mutates a current approved infographic. Independent launch must not import other pipelines or require Marketing Studio executable.

Sharing is optional and explicit, keeps local Store root/owner and blobs in place. Use configured shared repository and an independent private clone/cache, fixed owned infographics/ namespace and selected-file inventory. Default share approved deliveries/readable summary only; source captures, editable project and artwork require separate explicit inclusion, prompts never implicit. Show exact files/bytes/privacy/missing-asset state before commit/push. Shared driver claim metadata supports read-only view, handover and explicit takeover; remote expected commit/claim guards and non-fast-forward rejection prevent concurrent silent overwrite. A supported editable take imports a new locally owned project revision without approval; missing sources/assets remain honest blocked states, while earlier shared delivery stays readable. No bulk local-directory upload and no automatic push on unrelated edits/setup/status. Use existing shared Git/process lock infrastructure where independent interfaces permit, no shell/force-push/hooks. Synthetic bare remotes, separate local identities, foreign-owner conflict, dirty clone preservation, failed push/offline retry, missing assets, selected inventory and refresh tested.
