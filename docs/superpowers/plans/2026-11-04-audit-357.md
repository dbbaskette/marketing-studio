# Research queued-note status — #357

## Spec and plan

A note is queued only when its current text and basis equal the acknowledged
private draft. Unsaved edits survive a Review remount in memory and keep an
explicit unsaved label. Saving, failed saves and stale-basis warnings remain
truthful. No note changes research scope, evidence, or checked output.

1. Derive status from current versus acknowledged state, including after remount
   and after a delayed save response.
2. Exercise Save A → type B → remount, reload, failed save, delayed acknowledgement
   and earlier-basis warnings using the real shared Intake implementation.
3. Run shared research component/note checks and one synthetic browser journey.

| Transition | Expected status |
| --- | --- |
| Empty read | No queued note |
| Save A acknowledged | Queued privately |
| Type B then remount | B retained, not queued until saved |
| Reload | A restored as the acknowledged note |
| Save fails/conflicts | Failure visible, B remains unsaved |
| Save A finishes after typing B | B remains unsaved |
| Section basis changes | Earlier-revision warning retained |

Verification is owned by this implementation; no pipeline or provider jobs run.

## Result

Shared research-page and private-note modules passed with real Intake behavior.
The synthetic browser reproduced Save A, type B, Home, Review: B remained visible
and explicitly unsaved; reload restored A. Failed saves, delayed acknowledgement
and earlier-basis warnings passed in the shared component harness. No research
request or pipeline state changed.
