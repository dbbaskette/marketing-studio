# Blog Studio unfinished intake — #356

## Spec

An unfinished New blog or Polish a draft form resumes after navigation/reload with
its step, brief, writing choices, selected source identities, captured research
reference and pending file inputs. Save and close and confirmed Discard draft are
explicit. Drafts are private to this computer/workspace, revision checked, and
never create a blog, launch an assistant or synchronize team content.

Start first acknowledges the form; the existing stable operation identity makes
retries idempotent. A successful start clears only that acknowledged intake. A
new preset must explicitly replace a different unfinished form. Credentials,
DOM objects and transient busy states are excluded from persistence.

## Plan and verification

1. Add a bounded private intake route using the shared revision/lock store before
   any team fetch/share path. Reads create nothing; authenticated local drafts bypass remote team access checks.
2. Bind the existing two-step/polishing forms to a whitelisted Intake adapter.
   Preserve file bytes privately and source IDs without re-uploading on restoration.
3. Add visible saving/error state, Save and close, confirmed discard and navigation
   flush. Keep failed saves and conflicts visible with answers retained.
4. The implementation owner verifies reload, navigation, source references, files,
   conflicts, discard and idempotent Start using synthetic state and disabled jobs.
   Run complete affected intake/start/UI modules, then relevant full verification
   through the shared Tart infrastructure at the integration milestone.

## State transitions

| State/action | Result |
| --- | --- |
| First visit/read | No draft file or project created by the read |
| Input/step change | Private incremental revision save; no assistant |
| Reload/reopen | Restore current draft and operation ID |
| Save and close | Navigate only after save acknowledgement |
| Stale tab save/start | Refuse and retain local answers; no project/job |
| Confirm discard | Clear only matching private draft; captured sources remain |
| Successful Start | Existing idempotent creation; clear acknowledged form |

## Review focus

No shared-state write from autosave, no serialized browser objects or credentials,
no false saved status during file encoding, and no silent replacement of another
tab's draft. Existing source readiness checks still own whether Start may run.

## Verification evidence

- Complete management JavaScript harness passed, including private persistence,
  file-byte restoration, source identities, step/operation retention, stale save
  refusal, no Start after failed save, Save and close and explicit discard.
- Synthetic browser: brief and writing preferences survived Save and close, Home,
