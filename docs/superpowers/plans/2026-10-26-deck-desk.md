# Piece 5, the deck desk in Presentation Studio: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** new decks from the page start in three steps and run with no stops, except a look
pick the person chose. They open on one desk with a card per slide: a note that redraws only
that slide's section, a whole-deck note with Stop, word and selection edits, speaker notes as
their own edit, History per slide, the Outline tab, Add a source and Finishing. Delivery,
revisions, brand-check blockers, the team claim and every saved deck keep working.

**Architecture:**
- **The marker.** A desk deck is a run record with `flow: 'desk'`. It runs the same
  `stages.PIPELINE` as any other deck.
- **Its gates.** They are met by a new `Engine._desk_gate`, which leaves a receipt
  `by: 'desk'`. `gate:look` waits only when the start chose to pick. `gate:build` waiting is
  the desk.
- **Desk actions** are engine methods in a new mixin, `runner/desk_actions.py`. Each one
  records an ask and reopens `gate:build`. The engine's own steps then do the work:
  sections, whole, render.
- **Assistant jobs that are not pipeline steps** (words, speaker notes) are queued in
  `run['desk_jobs']`. `_work` takes them before its next step.
- **Pure helpers** live in `runner/desk.py` (record, view, prices, sentences) and
  `runner/steps/words.py` (patching a drawn section's words).
- **The page** is a new plain script, `scripts/desk/deck-desk.js`, beside `app.js`. It is
  built on piece 3's `ui-kit/drafting.js`.
- **Old runs** keep `app.js`'s gated screens unchanged.

**Tech Stack:**
- Python 3.11 standard library.
- Plain JavaScript and CSS with no build step.
- `unittest`.
- Presentation Studio's `tests/page_harness.js` (Node, no packages).
- The stand-ins in `tests/runner_support.py` and `tests/stand_ins/`.

**Spec:** `docs/superpowers/specs/2026-10-26-deck-desk-design.md`. Read it with this plan,
starting from its "Decisions for the owner". This plan builds the recommended choices. The
owner took every recommendation on 2026-10-26.

## Global Constraints

- Pieces are built in order (1 to 6), each merged before the next starts. Line references are at
  main cc53056: re-read every named file on the piece's own base first. Training matrix row
  numbers named here are a guide; each new row takes the next free number on that base.
- **Code.** Python 3.11 or newer, standard library only; no frontend build step.
- **Names.** Full product names in code, docs and commits: Marketing Studio, Presentation
  Studio, Blog Studio, Training Studio, Harness Slides, Harness Research. Presentation
  Studio names no brand (`tests/test_no_brand_named.py`).
- **Words.** Person-facing sentences never say "artifact", "stale" or "lineage", and never
  show a hash or digest.
- **Delegation.** Research stays in Harness Research and slide building in Harness Slides.
  The studio never edits a .pptx by hand: Selected changes use `pptx patch` and
  `pptx compare` only.
- **Layout.** UI follows `docs/design/golden-gate.md` and piece 4's layout:
  - one filled button a screen (**Deliver** on the desk);
  - glass only on the toolbar, the selection bar and sheets;
  - cards and forms opaque;
  - controls at least 44px.
- **Shared settings** go only through the studios-config file and its lock. This piece
  writes none.
- **Tests** use disposable data folders (`PRESENTATION_STUDIO_DATA` via `tests/helpers.py`),
  workspaces, Git identities and studios-config files, scripted workers
  (`runner_support.Workers`) and the stand-ins. No provider job, no Google, no network.
- **`main` is live.** Guidance that needs a script change raises `minimum_runtime` in
  `studios/presentation/guidance/manifest.json` and `studios/presentation/VERSION` together,
  to the next minor version above the base (4.5.0 at cc53056).
- **Saved decks keep working.** A run without `flow: 'desk'` takes no desk path. Every
  task that touches a shared path has a test with a gated deck.
- **Running tests.** One file at a time: `cd studios/presentation/tests && python3 -m
  unittest test_deck_desk -v`. The whole suite: `cd studios/presentation/tests && python3
  -m unittest -v`. Tests that bind ports fail inside the sandbox, so run those on the
  shared Tart runner.
- **Commits.** Messages are plain sentences. End each with the attribution line the
  session gives.

## Review Focus

1. A run without `flow: 'desk'` never takes a desk path, and a desk deck never takes a gate route (Task 1.3).
2. A slide note leaves every other slide in its section byte for byte the same, and a note is never sent to a composer twice (Task 1.5).
3. Deliver is bound to the deck hash on screen and to the blockers the person saw, and a desk receipt is never `by` a person (Tasks 1.2, 1.9).
4. A word or notes edit lands whole, with no composer job, or saves nothing (Tasks 2.1 to 2.3).
5. A computer without `work/` never redraws a desk deck unasked, and desk work settles only on the driving computer (Task 1.10).

### Task 1.5: The slide note redraws only its section

**Files:** Modify `runner/desk.py`, `runner/desk_actions.py`, `runner/steps/build.py` (`section_work` 1159, `keep_section` 1326) and `runner/engine.py` (`_sections_for` 1831 is unchanged; a new caller); Test `tests/test_deck_desk.py`.

**Interfaces (Produces):**
- A desk note is
  `{'id': token, 'slide', 'number', 'section', 'note', 'at', 'by', 'status': 'waiting'|'drawing'|'done'|'set aside'}`
  in `run['desk_notes']`.
- `desk.BUSY = 'Slide {number} is being redrawn now. Your note is kept here; send it when that ends.'`
- `desk.LEAD = 'A cover, section or closing slide is not drawn by an assistant: change its words on the Outline tab.'`
- `desk.CHANGED = 'The deck changed since this page read it. Reload it, then try again.'`
- `desk.section_of(state, number) -> str | None` returns None for a lead slide.
- `desk.add_note(run, state, number, note, at, by) -> dict` raises `BUSY` when the section
  has a `drawing` note.
- `desk.pending(run, section) -> list[dict]` returns the `waiting` and `drawing` notes.
- `desk.settle_notes(run, section) -> None` turns `drawing` into `done`.
- `desk.ask(state, sections) -> None` sets
  `state['asked'] = {'note': None, 'sections': union, 'at': now}` and `repaired = 0`.
- `DeskActions.desk_note(path, number, note, expected) -> view`:
  - It checks `expected == last['deck']`, and refuses with `CHANGED` otherwise.
  - On a deck this computer delivered, it calls `_take` and then `delivering.again`.
  - It adds the note, calls `desk.ask`, and marks the section's notes `drawing`.
  - When `gate:build` is waiting, it sets the gate to `{'state': 'changes', 'by': 'desk'}`
    and reopens it with `stages.reopen`, so `_gate` runs again at the end of the chain and
    the deck waits on the desk again. A deck already in its chain is only asked.
  - It commits "ask to redraw slide {n}" and calls `wake`.
- `desk.reopen(record) -> dict` does that gate change and reopen, for every desk action
  that redraws or puts the deck together again.
- `section_work` changes on a desk deck. It reads `desk.pending(run, section)` in place of
  `build_feedback`, and it focuses those slides, so every other slide in the section is
  frozen as `unchanged_slides`.
- `keep_section` calls `desk.settle_notes` on a desk deck.
