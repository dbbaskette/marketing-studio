# Large-workspace compact polling — #359

## Spec

Each signal request retains the 5,000-entry/75 ms metadata budget. An incomplete
scan resumes on the next request instead of restarting. Completed fingerprints
are order independent, include every path and metadata identity, and detect
external edits and non-selected projects. Content and symlink targets are never
read. Directory depth and open iterator storage are bounded.

`complete` means this request completed its scan. A separate `cached` flag allows
reuse of a previously completed revision for at most 30 seconds while a new scan
progresses. A partial scan is never reported complete. Before the first complete
scan, after cache expiry, on scan error or with a zero budget, fall back to full
reads. Clients retain active-job reads, immediate noncompact catch-up and a full
authoritative read at least every 60 seconds. No background worker or dependency
is added. The engine owns its scan and serializes concurrent signal requests.

## Implementation and validation plan

1. Implement resumable metadata traversal and age-limited completed fingerprints.
2. Teach both native clients to distinguish a cached result from scan completeness.
3. Cover entry/time exhaustion, expiry/error fallback, symlink/depth safety, edits,
   additions/deletions in non-selected projects and active jobs.
4. Benchmark unchanged flat and many-project/asset synthetic trees above the old
   limit, comparing signal duration and modeled authoritative counts/bytes under
   the actual client polling policy. Record update visibility and limits.
5. Run affected core/native polling checks and full relevant native verification
   through the shared disposable Tart runner before merging.

Large-workspace updates become visible when the next scan completes, or through
the unchanged 60-second authoritative catch-up bound, whichever occurs first.
Small workspaces still complete a fresh scan on each request.

## Evidence

Seven focused core/native-policy checks pass, including overlapping roots and
concurrent probes. The benchmark and native HTTP observations are documented in
`docs/incremental-polling-measurement.md`. The live Training Studio browser made
eight idle probes without full content reads; external refresh preserved the
selected slide and worker count. Broad shared/native suite results are recorded
in the pull request, with final fingerprint checks repeated in the same guest.
