# Marketing Studio: compact creative launchpad

Keep the current four-studio launch workflow, but replace the large empty card
middles with useful hierarchy and small output-format illustrations. This is a
visual refinement of the existing Golden Gate-inspired home, with no new backend,
project content, job-start behavior or dependencies.

Design: system typography, the existing neutral canvas/opaque cards and each
studio's existing accent/wash. Keep glass in the shell. Each compact card presents
product identity, a concrete task description, a decorative SVG output specimen,
real readiness and its launch action. Workspace/version information moves into
an accessible Details disclosure. Connection warnings and Connect remain visible.
No invented recent projects, generated examples, progress or fake content.

Use two balanced columns on desktop, four peers on wide screens and one column
on a phone. Short Open/Return/Install labels retain full accessible product names.
Natural card heights and
a shared footer replace the 19rem minimum and stretched empty grid row. Details
expands naturally. Maintain long-label wrapping and 44px mobile controls. Focus
and real launch/connection states retain their current behavior.

| State | Required behavior | Verification |
| --- | --- | --- |
| Ready, stopped or running | Show current readiness and the correct Open/Return action | Existing readiness browser |
| Needs connection | Visible explanation and Connect priority | Page/browser fixture |
| Not installed | Illustration is descriptive; install action and status remain explicit | Page/browser fixture |
| Details expanded | Repository, local path and version remain readable | Native browser |
| Phone/dark/reduced effects | No overflow, readable tokens and reachable controls | Native browser |
| Reading home | No launch, provider job or setup mutation | Existing page suite |

Verify real protected home pages with disposable settings and synthetic metadata.
Review screenshots at wide and narrow widths; check compactness, launch states,
keyboard/disclosure interaction and reduced effects. Run the complete relevant
shared/home suite once, package/UI checks and existing readiness coverage. Reuse
unchanged studio pipeline evidence. No personal app switch/restart or publishing
is implied by the visual request.
