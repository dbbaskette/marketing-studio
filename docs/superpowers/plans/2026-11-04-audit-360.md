# Issue 360 — slide correction conflict recovery

## Specification

A revision conflict must retain every local slide correction and feedback note, stop stale navigation writes, and keep approval blocked. Offer a complete selectable/copyable JSON recovery record and an explicit read of the latest saved corrections. Compare differing slide numbers and feedback; loading the latest version requires confirmation and retains the local recovery record in the page so the person can reconcile manually. Do not merge or overwrite automatically. A newer race after recovery must still receive the server's revision refusal. Existing outline-basis conflicts and exact-revision approval remain authoritative.

## Implementation plan

1. Add a failure hook and conflict/recovery state to the shared review draft adapter; leave other intake behavior unchanged.
2. Add one recovery panel with copy-all, compare and confirmed load-latest actions. Navigation alone cannot retry a refused write. Show errors once.
3. Exercise multi-slide edits, comparison, failed reads/writes, repeated remote changes, remount and recovery in shared component tests; run affected native approval checks and a disposable browser journey.
4. Push a dedicated pull request and merge after checks. Reuse the preceding shared/native full-suite evidence for unchanged code.
