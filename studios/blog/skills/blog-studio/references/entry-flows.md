# Entry flows

Interpret the request and already supplied material before asking anything.
Do not treat an implementation/demo request as a request to write a real article.

When the intent is open-ended, use an opening such as:

> How would you like to start? I can help with a draft you've written, write a
> first draft, build an outline, write from your outline, interview you, or help
> find an idea. You can attach material or share links along the way.

Use the host's text-choice widget if available for route selection. Ordinary
chat works everywhere. Avoid making a large intake form; the next question
should unlock the next stage. Voice setup is a seventh independent operation,
not an obligatory preliminary task.

| Path | Minimum useful context | Next capability | Stop point |
|---|---|---|---|
| Existing draft | Manuscript and desired help | Copy editing or requested review | Revised draft or feedback |
| First draft | Topic, reader, useful angle; reuse supplied details | Outline internally, then compose | First draft |
| Outline only | Topic or source material, reader, intended takeaway | Argument outline | Outline |
| From my outline | Outline plus enough context to expand accurately | Compose | Draft |
| Interview | Starting topic or experience; ask if absent | Author interview | Outline by default; draft if already requested |
| Discover idea | Audience/interests and purpose | Content strategy | Topic options/brief; continue if requested |

Offer source intake once when it is relevant and unanswered:

> Would you like to attach source content, paste notes, share links, reuse
> existing material, or continue without it?

Wait for the actual reply if the user says they will upload; do not treat an
empty response or elapsed time as the missing material. Reuse attachments
already supplied. If there are no sources, clarify supplied-only versus outside
research only when factual scope matters. Record the choice rather than asking
again at each handoff. Public research uses available search tools; link access
alone never supplies account credentials or permission to access private data.

Choose voice without interrupting a clear request: preserve imported-draft
voice; reuse an explicitly chosen profile; apply supplied tone instructions.
When there is no preference, offer a saved voice, build one, describe a tone,
or start in a clear conversational style. Lack of a profile need not block drafting.

Infer format and length from the request; ask only when consequential. Briefs
capture topic, audience, thesis/takeaway, format, length preference, research
policy, voice selection, selected material, required points, and stop point.
Unknown entries can remain unknown until needed; estimates are not user facts.

At the requested stop point deliver the artifact and meaningful open issues.
Suggest optional next steps concisely, without automatically doing them. An
outline can suggest drafting next; a draft can suggest review; review can suggest
repurposing/export. Do not turn every stage into a new approval ceremony.

Apply [data boundaries](privacy.md) before external extraction, public research,
media requests, or document posting. Generic research permission never includes
private queries; document posting includes only the selected content/destination.
