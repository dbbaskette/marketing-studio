# Visual explanations

Load when a diagram, screenshot or chart is part of the requested article.
Choose a visual to answer a reader question: relationships, sequence, a specific
UI action or measured comparison. A cover image is optional and does not replace
a technical explanation.

Use descriptive labels and explain the takeaway in adjacent prose. Define arrows,
units and abbreviations. Mark simplified architecture and omitted components;
do not imply a conceptual diagram is a tested deployment. Screenshots should
reflect the relevant version and exclude credentials or unrelated private data.

Provide useful alt text; explain complex diagrams in surrounding text. Do not
rely on color alone to distinguish states or series. Charts need legible units,
scales, baseline and evidence. Disclose truncated axes or different measurement
conditions; preserve meaningful variation rather than decorating a single result.

Prefer editable diagrams and selectable code where helpful. Never use a screenshot
as the only copyable command. Authoring or requesting a visual is not permission
to send private content to an image provider; follow existing media/privacy scope.
If no suitable asset is available, deliver the requested prose with a specific
asset note instead of blocking or inventing a finished visual.

Basis: Google's images/accessibility guidance; [source map](sources.md).
