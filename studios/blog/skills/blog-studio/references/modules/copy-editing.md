# Editing guide

For software-product edits or a requested house-style pass, use the
[house guide](../style/house.md). Apply it only to the authorized passages/depth;
its optional references do not expand a polish into research or restructuring.

Keep private inputs in the existing harness and selected private hub. Apply
[data boundaries](../privacy.md) before external research, media, or document
posting; upstream suggestions do not authorize disclosure.

Use for proofreading, polishing, developmental feedback, or an agreed refresh of
existing copy. Start with the manuscript, desired edit depth, selected voice, and
known concerns. Deliver the requested revision or located feedback. Use this guide for routine edits.

## Establish what may change

Preserve the core message and author's stance. Read neighboring context for a passage edit and the full article for a whole revision. Reuse supplied audience/voice context. A clear passage-edit request needs no setup menu or per-sentence approval.

Save the untouched original before revising an imported manuscript. Feedback-only
does not replace it. Existing articles retain pinned source, voice, and guidance
revisions. An unrelated profile update is not permission to change their style.
Do not promote an edited/generated passage into a durable voice sample.

## Choose relevant editing lenses

A quick polish normally needs clarity and voice. Add structure, evidence, or
persuasion lenses when the actual request or a material defect calls for them.
Select lenses; seven passes and scoring are not compulsory.

- **Clarity:** resolve ambiguous pronouns, missing context, overloaded sentences,
  and abstractions that obscure an action. Prefer the precise familiar word,
  but keep technical terminology when simplification changes meaning.
- **Voice:** preserve perspective, formality, humor, and deliberate phrasing.
  Smooth accidental tone changes. Author rules outrank generic word-ban lists;
  quoted text, code, and links require special care.
- **Reader relevance:** explain why an observation matters. A capability can
  connect to a supported practical benefit; do not invent a result to make it
  persuasive. Educational prose can end with understanding rather than a sale.
- **Evidence:** flag assertions stronger than their source, unsourced superlatives,
  false precision, missing attribution, or changed qualifiers. Distinguish
  unsupported from contradicted; a hedge does not remove the underlying claim.
- **Specificity:** replace vague praise with an available concrete action or
  example. If no number or case exists, do not fabricate one. “Names the next
  owner” can be useful specificity; “saves four hours weekly” needs evidence.
- **Structure:** give each section a distinct contribution, remove repeated setups
  and examples, and make transitions explain how the next point follows. Preserve
  requested headings/order unless restructuring is within scope.
- **Persuasion, when requested:** make the real benefit and next action clear,
  address evidenced objections, and set accurate expectations. Never invent
  urgency, guarantees, testimonials, risk reversals, or privacy assurances.

Recheck earlier strengths after substantive edits; focus on changed meaning,
evidence, emphasis, or voice.

## Make useful repairs

A finding should identify an exact passage, explain its effect on the reader,
and offer a concrete replacement or action. Prioritize factual contradiction
and broken reasoning before cosmetic preferences. Separate a required correction
from an optional stylistic alternative so the author can judge the tradeoff.

For developmental feedback, explain the missing reasoning or example and where
it belongs; ask for facts only the author can supply rather than writing a
fictional case. For passage edits, make the replacement fit the neighboring text.
For whole-article changes, maintain names, stance, terminology, and transitions.
Use [controlled revision](../revision.md) only when this additional mode guidance
is needed.

Preserve names, units, dates, quotations, URLs, and material qualifiers unless
their correction is supported and within scope. Read originals and sources for
semantic equivalence; a mechanical token comparison catches some changes but
cannot establish that meaning is unchanged. Avoid “fixing” accurate expert terms,
dialect, or quoted language solely to satisfy a readability target.

## Return and save the result

Apply already authorized edits, then report the material changes and remaining
evidence gaps once. Feedback-only returns findings; a requested rewrite returns
the rewritten text. Read back saved work using the [workspace router](../workspace.md) and article
operation; prior versions remain recoverable and affected checks become stale.

If asked to record a review, use the focused review-storage instructions and
report its actual coverage/status. Failed, unavailable, or absent checks cannot
produce a clean verdict. Imagined panels are not independent reviews. Polish proves neither authorship nor ranking.

For repeated mechanical checks or a focused passage request, use
[exact-input reuse and excerpts](../workspace/performance.md). Whole-article
editing still requires reading the whole article.
