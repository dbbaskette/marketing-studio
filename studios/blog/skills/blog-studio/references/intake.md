# Material intake

Accept attachments, workspace files, pasted content, and URLs through actual
host tools. Read [source intake](modules/blog-source-intake.md) for normalization.
Classify each item by its intended role, inferring from an explicit request:

| Purpose | Use |
|---|---|
| manuscript | The article being edited; retain original |
| outline | Author-supplied structure |
| reference | Factual support, with source attribution |
| inspiration | Topic/structure example; not evidence or author voice by default |
| voice-sample | Confirmed authored writing selected to learn style |
| author-background | Bio, role, expertise, preferences; not invented experience |

A source may have multiple roles. A public blog by someone else is not a voice
sample for the author. If authorship or purpose affects the work and is unclear,
ask one concise clarification. Item roles can differ between articles.

Preserve original bytes and an extracted text version. Record name, origin URL
or filename, author if known, purpose, status, content hash, extraction/retrieval
date, and limitations. Keep quotes attributable to an exact source passage.
State if only an excerpt or truncated version was read. Deduplicate exact
content when useful, without discarding distinct provenance or roles.

Do not silently turn an inaccessible page, parsing failure, or summary snippet
into a full source. Record unavailable/pending and explain the practical next
step: attach a copy, paste the passage, or use another source. For PDF, Word,
slides, or spreadsheets use host extraction tools and relevant available skills;
do not pretend the dependency-free storage helper extracts those formats.

Select only material relevant to the current article/stage. Reference documents and linked-page snapshots are retained for later blogs;
see [reference memory](workspace/reference-memory.md). The source library
can grow without every source entering every prompt. Read full evidence when
checking a specific claim. Keep excerpts linked to their original record.
Use the [source storage](workspace/sources.md) to record source files and attach
selected items. Do not automatically ingest an entire directory or account.

Apply [data boundaries](privacy.md) before external extraction, public research,
media requests, or document posting. Generic research permission never includes
private queries; document posting includes only the selected content/destination.
