# Editorial tools and management interface

Approved scope: Epic #29 children #39–#44 plus the requested management interface,
README, and user documentation. Keep the interface in this repository, backed by
the selected workspace/private Git Hub. No new hosted service, credential store,
repository, scheduled crawl, or publication is introduced.

Deliver six focused capabilities: review/attention inbox; revision-bound launch
packages; source-grounded visual companions; claim-to-passage evidence; editorial
board with explicit owners/due dates; generic historical blog collections with
previewed bounded import, refresh, search, pinned references and source-linked
candidate lessons. The local management UI browses local and shared work, links
Google Docs, uploads/curates documents, and inspects/edits scoped memory. Reading
Google review data is explicit and capability-bound; historical saved data is
labeled. Live pilots remain #9/#10/#15 and the bounded collection pilot remains
explicit rather than claiming fixture evidence proves live support.

Shared data stays in existing article/source/memory revisions. Derived assets
carry manuscript/source provenance and stale on changes. A ready editorial stage
requires an explicit decision; author, owner and last editor remain distinct.
Uploads retain originals; unsupported extraction stays pending. Generic imports
never treat retrieved instructions as commands or historical claims as current
facts. Candidate lessons require deliberate promotion to shared rules.

Local HTTP boundary: loopback-only server, per-run token, Host/Origin checks,
restricted methods/routes, bounded body/file sizes, no arbitrary path endpoints,
text-safe rendering, no external scripts/fonts/media, restrictive CSP. URL import
is explicit to previewed collection scope, validates resolved public addresses,
pins the actual connection and revalidates every redirect. No private authenticated
site scraping or new account setup. Exact version/history and contribution policy
remain under existing Hub locking and immutable graph machinery.

UI direction: a working editorial desk with a strong navy sidebar, pale blue page,
teal actions, orange attention markers, readable system type, table/list hierarchy,
mobile navigation, keyboard focus and empty states with the next useful action.

Access decision: everyone with existing Hub write access uses the same controls;
no separate application roles. GitHub manages membership. Ordinary Pages is public,
so this delivery uses localhost for management and private GitHub Markdown views.
